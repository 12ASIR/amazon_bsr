# AM 竞品宽表监控 — 项目提示词

> **合并说明**：本文档为模块化提示词，可与其它项目提示词合并使用。
> 本模块只负责「Amazon 美国站竞品监控宽表」这一部分，不与其它业务模块混用字段与口径。
> 若与其它模块表述冲突，以本模块为准；合并时保留本文档全部小节，不要删减「工程约束」与「明确不做的事」。

---

## 1. 项目目标

将卖家精灵「流量时光机_流量变化」的多份导出文件，合并为**一张单 Sheet 竞品宽表**，
让运营一眼看清：谁改了标题、谁改了主图、谁上了券、谁调了价、谁的排名异动需要重点关注。

产出两份等价文件：Excel 宽表 + 单文件 HTML 网页看板。两者数据同源、必须一致。

---

## 2. 目录约定

项目根目录固定为 `AM竞品数据-sif`，内部结构如下：

```
AM竞品数据-sif/
├─ 1-数据源/      按日期分子目录（如 20261111/），每目录放当日抓取的导出文件
├─ 2-脚本/        build_competitor_wide_table.py、asin_map.csv
└─ 3-输出/        竞品宽表_YYYYMMDD.xlsx、.html
```

约束：

- **路径一律不写死**。项目根由 `Path(__file__).resolve().parent` 推导（脚本在 `2-脚本` 内取上一级）。
- 数据源目录名、脚本目录名、输出目录名以常量声明（`DATA_DIR_NAME / SCRIPT_DIR_NAME / OUTPUT_DIR_NAME`）。
- 数据源目录**递归扫描**，新增日期子目录无需改代码。
- 输出目录不存在时自动创建。
- 脚本同级不存在 `2-脚本`（旧的扁平结构）时自动回退兼容，整套目录可搬到任意路径运行。

## 3. 数据源与取数规则

| 项 | 规则 |
|---|---|
| 来源 | 卖家精灵「流量时光机_流量变化」导出 |
| 单文件结构 | 约 72 行 × 40 列，含约 71 天逐日趋势 |
| 数据日期 vs 文件名日期 | 文件名日期＝导出日，**数据最新一行＝T-1**，取数一律按数据日期列判定，不看文件名 |
| 每个文件取数 | 取该文件中**最新数据日期那一行**作为该 ASIN 的快照 |
| 多文件同 ASIN | 同 ASIN 存在多份导出时，取**数据日期最新的一份**，避免重复计数 |
| ASIN 来源 | 从文件名用正则 `B0[A-Z0-9]{8}` 清洗得出，不从表内猜 |
| 数据源数量 | 单日期源即可，无需额外准备两个日期文件（源表已含 71 天历史，足以做环比） |
| 数据滞后提示 | 某行数据日期落后于全表最新日期时，该行加浅橙底提示 |

源表中全空或无意义的列（Prime 会员价、LD 秒杀价、SBV 流量及占比等）不入宽表。
源表没有独立「文案」列时，列名诚实写作「改标题」，不得命名为「改文案」。

## 4. 输出形态

- **只要一个 Sheet**，不建辅助 Sheet、不建说明页；口径写入文件属性的同时以顶部口径条呈现。
- 列数以「够用」为准，保留核心列、删除可反算的冗余列（如源表自带的环比变化值/百分比）。
- 表头分区深蓝底、冻结首行与 ASIN/品牌列、开启筛选、关闭网格线、列宽自适应。
- 数字用单元格格式呈现（小数/千分位/百分比），**不 round 改值**，保留源值原精度。
- 变更类标记列：只显示「是」，未发生留空；「否」与「字段缺失」要区分，不能混为同一含义。

核心列顺序（35 列，节选关键）：

`ASIN → 品牌 → 适配车型 → 价格与排名快照 → 变更标记列 → 排名异动 → 当日变动摘要 → 近7天动作`

## 5. 计算与判定口径

| 维度 | 口径 |
|---|---|
| 时区 | 固定 `America/Los_Angeles`（美西），不随本机时区变化；以常量声明 |
| 价格 | 监控 **Buybox 价**为核心，成交价不单独列；数值变大＝提高，变小＝降低，不变不写进摘要 |
| 券 | 单列展示 Coupon($) 金额 |
| 排名 | 数值**变小＝上升**，变大＝下降 |
| 小类排名警示 | 绝对位差 **> 20 位**（`RANK_ALERT_SUB_THRESHOLD = 20`） |
| 大类排名警示 | 相对幅度 **≥ 10%**（`RANK_ALERT_MAIN_RATE = 0.10`），公式：位差 ÷ 前一日 BSR |
| 排名文案 | 分开写：「小类下降 45 位」「大类上升 29.6%（21,899 位）」 |
| 近7天动作 | 取最近 7 个有数据的交易日；连续同值动作折叠为日期区间，如 `11-05~11-09 券$13.4` |

**优惠券动作判定（纯规则，写死在脚本里）**

| 序列变化 | 判定 |
|---|---|
| 无券 → 有券 | 券上新 $X |
| 有券 → 无券 | 券结束（原 $X） |
| 金额变化 | 券调整 $A→$B |
| 连续多日同额 | 折叠为日期区间 |
| 窗口内无券 | 留空 |

券事件必须**同时**出现在「当日变动摘要」与「近7天动作」两处，不得只写一处。

---

## 6. 文案与展示规范

**看板顶部口径说明：固定 8 条，每条一行、不超过一行宽度，只留必要口径，禁止解释性长句与重复表述。**

```
· 时区：美西时间（America/Los_Angeles）
· 数据日期 YYYY-MM-DD，对比日期 YYYY-MM-DD
· 竞品 N 个
· 价格：看 Buybox 价，涨＝提高，跌＝降低
· 排名：数值变小＝上升，变大＝下降
· 警示：小类变动＞20 位，大类变幅≥10%
· 券：无券→有券＝上新，有券→无券＝结束，金额变＝调整
· 标记：「是」＝当日发生，空白＝未发生
```

- 口径文案只允许存在**一处**（`legend_items()`），网页与 Excel 同源渲染；阈值改常量时文案自动跟着变。
- **当日变动摘要**：只保留「动作关键词＋关键数值」，顿号连接，去掉引导词、括号注释与重复信息。
  示例：`小类↓45位、大类↑29.6%、券上新$13.4`；金额去尾零（$13.40→$13.4）；整列单行可读。
- 网页看板需支持：搜索、筛选、排序、导出 CSV、导出 Excel。

## 7. 工程约束（硬性）

1. **零 AI 判断**：所有动作、涨跌、券事件的判定，必须由源表字段与逐日序列的确定性规则推导。
   禁止硬编码结论、禁止人工补录、禁止依赖模型总结。重跑结果必须逐字节可复现。
2. **动作顺序固定**：由 `ACTION_ORDER` 常量决定，同日多动作按该顺序顿号连接。
3. **自我核对**：末尾内置 `verify_workbook()`，回读产出文件逐项与源表比对（数值、文本、日期），
   不一致必须报错，不得静默通过。每次改脚本后重跑并报告核对项数与不一致数。
4. **独立复核**：除了脚本内置核对，另写一份不复用主脚本任何函数的独立脚本，直读源文件复算关键列，
   交叉验证。两套结果都要 0 不一致才算完成。
5. **映射表外置**：ASIN 维度不写在代码里，统一读 `asin_map.csv`（UTF-8 BOM，Excel 可直接打开），
   列固定三列：`ASIN, 品牌, 适配车型`。缺映射时留空并继续运行，不得中断、不得编造。
6. **缺字段留预留逻辑**：源表没有的字段，程序要有预留位并标注「字段缺失」，不可与「否」混淆。

## 8. 已知的坑

| 坑 | 说明 |
|---|---|
| 排名警示全亮灯 | 大类排名基数万级，用「20 位」绝对值判会让所有行都触警，故大类必须走 ±10% 相对幅度 |
| 券结束漏记 | 券从有到无的变化容易被忽略，只做「上券」不做「撤券」会导致摘要失真 |
| 循环变量未绑定 | 排序 lambda 引用循环变量会抛 `NameError`，需绑定取值（如 `x[2]`） |
| 数值格式差异 | 复算脚本用 `%.2f`、主脚本去除尾零，会被误判为数据不一致，核对前先对齐格式口径 |
| 导出日 ≠ 数据日 | 按文件名日期取数会错位一天，必须读表内数据日期列 |
| 同 ASIN 多份导出 | 不做去重会导致同一 ASIN 重复计入、环比算错 |
